## Candidate boundary

The prerelease exposes the accepted command-line work through CLI Contract 2:

- deterministic raw and semantic DOT output, including topology, logical,
  protection, power, dependency, and overlay views
- semantic clusters, endpoint ports, and relation lenses for readable diagrams
- explicit link, link-aggregation, channel-bonding, STP, ring, protection-domain,
  and K-of-N resilience modeling
- bounded path, qualified-SPOF, and declared-failure analysis with deterministic
  human and `ltfa.assurance/v1` JSON output

The same source tree also contains the accepted offline observation and
diagnosis core: pinned yyjson decoding, evidence indexing, deterministic
diagnosis, Graphviz diagnosis output, and a redacted history fixture. These are
source-tree C++ APIs only. This candidate does not install an SDK and does not
add an observation or diagnosis CLI command.

The candidate retains the one-shot offline boundary. It does not add network
probes, command execution, databases, plugin loading, daemons, secret access,
or runtime dependency discovery. Slice 4 bounded cuts, benchmark gates, stable
`v0.3.0` promotion, and latest-release promotion remain outside this release.

## CI and publication boundary

The repository contains no GitHub Actions workflow, so the local matrix is the
candidate acceptance authority. After `main` is published, GitHub Actions,
check-run, and commit-status state must be read back for the exact candidate;
zero configured signals are reported as neither failure nor CI success.

No local or remote `v0.3.0-alpha.1` tag exists at candidate acceptance.
Publication must:

1. push the exact candidate on `main` through the approved credential boundary
2. read back the remote branch SHA and CI signal state
3. create an annotated `v0.3.0-alpha.1` tag at that exact candidate
4. push only that tag through the approved credential boundary
5. compare the local tag object, remote tag object, and peeled commit

GitHub Release creation and stable-version promotion are separate operations
and are not authorized by this candidate.
