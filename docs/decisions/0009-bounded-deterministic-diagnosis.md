# ADR 0009: Bounded Deterministic Diagnosis

Date: 2026-07-31

Status: Accepted

## Context

The observation evidence index resolves registered probe semantics, retains
freshness and conflicts, and deliberately makes no target-state claim. Slice 3
next requires graph-aware diagnosis that remains reproducible and explainable
without converting ICMP timeout into device-down, inventing failure
probabilities, or enumerating an unbounded set of combined failures.

The reviewed design requires causal-cone candidate generation, single-failure
simulation, lexicographic evidence ranking, explicit ties, topology
qualification, and structured budget exhaustion. Identical model, evidence,
reference time, and budgets must retain identical result order.

## Decision

`diagnose_observations` is a public, value-oriented core API. It receives a
normalized model, an already validated `EvidenceIndex`, and explicit
`DiagnosisBudget` values. It reads no clock, file, network, process, plugin,
database, or credential source.

Only each evidence group's complete `latest` range participates. A fresh
`fail`, `timeout`, or `error` observation seeds diagnosis. A stale latest
observation also seeds diagnosis but cannot score as current evidence. Fresh
`pass` and `unknown` observations alone do not create failure hypotheses.

The causal cone starts at both the target and vantage of every seeding probe
and traverses only reverse normalized availability dependencies. It therefore
contains objects that can causally affect the registered target or vantage,
not unrelated topology. Traversal and the returned cone use stable external-ID
order. Reaching `max_causal_objects` returns `incomplete` with the exact
`causal-cone-budget` reason.

For every retained cone object, diagnosis creates:

- one hypothesis for each declared failure mode targeting the object; and
- one generic unavailable-object fallback hypothesis.

Every hypothesis is simulated independently from the all-available normalized
baseline through the existing deterministic propagation engine. Multi-failure,
failure-domain, and relation combinations are not generated by this API. They
remain separate bounded-analysis work rather than being silently mixed into a
single-failure ranking.

Fresh latest evidence is assessed as follows:

- `pass` contradicts a simulated loss of its target or vantage;
- `fail`, `timeout`, or `error` supports a hypothesis only when simulation
  predicts target or vantage loss;
- a non-pass not predicted by the hypothesis remains unexplained;
- stale evidence, an `unknown` outcome, or a simulated `degraded`/`unknown`
  probe endpoint remains unknown.

In particular, an ICMP timeout remains vantage-specific missing reachability.
It causes no direct availability transition. Only an explicitly labeled
single-failure hypothesis is simulated, and current evidence from another
vantage can contradict that hypothesis.

Findings are ordered lexicographically by fewer contradictions, more explained
non-pass observations, fewer unexplained non-pass observations, declared-mode
specificity, fresher evidence, better modeled evidence quality, and finally a
stable identifier. The stable identifier makes serialization order
deterministic but is excluded from rank equality. Equal score groups receive
the same dense rank and `tied=true`; no probability or pseudo-confidence value
exists in the contract.

Every finding retains all assessed latest evidence, explicit conflicting
evidence indices, affected objects, scope-derived completeness and evidence
quality, propagation unknowns, detection gaps, and stale, unknown, or
unexplained evidence as remaining unknowns. `partial` and `unknown`
qualification therefore remain visible rather than becoming an unqualified
state claim.

Four diagnosis bounds limit causal objects, hypotheses, simulations, and total
evidence comparisons. Propagation keeps its own event and state-transition
bounds. Exhaustion returns a deterministic completed prefix with
`DiagnosisStatus::incomplete` and one or more stable reason values. A partially
simulated or partially scored finding is never exposed. Structurally invalid
model or evidence input returns `invalid` and no findings.

## Consequences

The diagnosis core can explain why candidates rank above or below each other
using direct counters and evidence indices. It does not claim that the first
candidate is the actual fault, that omitted topology is healthy, or that a
timeout proves target, link, or power loss.

This task added no CLI command or machine renderer. The redacted integration
fixture and byte-stable JSON/DOT rendering were subsequently accepted as
separate tasks in [ADR 0010](0010-redacted-historical-fixture.md) and
[ADR 0011](0011-diagnosis-machine-output.md). Next-observation recommendations,
bounded cut analysis, and live probe execution remain separate tasks and
authority boundaries.
