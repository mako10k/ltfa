# Turbo Ring forwarding and failure reachability

Status: implemented and verified under the owner's2026-10-14 request. User baseline: extend LTFA core to separate physical availability from logical blocking, reopen the backup path on ring failure, and compute reachability after switching. Generic Turbo Ring; v2-specific differences excluded. Preserve offline one-shot operation. Scope: LTFA implementation and tests; no website deployment or remote publication.

Discovery: ADR0005 provides protocol, membership, roles and normal-state, exact-fit descriptive input. Existing failure propagation is exact-fit physical availability; generic path analysis is partial-fit because it has no endpoint-owner forwarding and cannot process protocol membership. Reuse propagation and add a separate domain-qualified forwarding graph rather than silently change generic assurance semantics. Existing STP/RSTP/MSTP/ERPS/MRP declarations retain distinct protocol identity; their protocol algorithms are not claimed as Turbo Ring.

Basis: user-described normal block/release on fault; Moxa Communication Redundancy Manual5.0 chapter2 confirms blocked redundant segment and readjustment on ring disconnection. https://www.moxa.com/getmedia/4a80ee73-bb98-46ac-8b42-531919b37eed/moxa-communication-redundancy-manual-v5.0.pdf . Backup selection differs byversion, so consume explicitly declared backup membership instead of choosing one from unknown master/MAC/port data. No recovered timing inferred from vendor maxima or Ping. Output marks timing unknown.

Interface: additive core forwarding analysis and offline CLI domain selection. Consume normalized control-domain protocol=turbo-ring; member_of device/link declarations; link connects two registered network endpoints whose owners are member switches. Require connected simple cycle >=3 devices, degree2, no chords/parallel/self links; exactlyone declared blocking/standby/discarding backup and remaininglinks forwarding. Missing policy/protocol or physical state returns qualified incomplete/unsupported, malformed topology invalid with reason. One registered source device or source network endpoint-owner; when an endpoint is the source, its physical state constrains ingress as well as owner state. No automatic port bridging outside the selected domain.

Physical snapshot remains immutable. Logical forwarding has forwarding/blocking/unavailable/unknown. A definite failure of member link, ring port or member device opens the healthy backup; failed backup stays unavailable. Healthy normal ring blocks declaredbackup. Unknown availability never becomes definite failure: use definite and possible connectivity to classify targets reachable/unreachable/unknown, and mark results incomplete. Degraded means physically traversable with degradedqualification. Domain unavailable disables forwarding; unknowndomain yieldsunknown. Devicefailure disables incidentlinks. Unknown/offline propagation is kept separate from logicalblocked.

Outputs expose protocol/domain, qualifications/reasons, backup activation, perlink intrinsic physical state, effective segment availability and logical states, paths and perdevice reachability before/after declared physical failures, without old generic SPOF claims. Source unavailable is unreachable; unknownsource is uncertain. Multiplefailures produce actual partitions. Budget exhaustion is incomplete, never negativeproof. Deterministic stable-order output, restrictedIDs use existing explicitinclude policy. No network, database, runtime daemon or dependency added.
