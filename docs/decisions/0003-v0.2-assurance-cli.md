# 0003: v0.2 Offline Assurance CLI Contract

Date: 2026-07-29

Status: accepted

## Context

The accepted Slice 2 core can calculate paths, qualified SPOF findings, and
single-failure propagation, but the installed `0.1.0` artifact exposes only
model validation and rendering. Tagging the current tree as a functional
`v0.2.0` would therefore advertise behavior that installed users cannot invoke.

The current local implementations of `secexec` and `perttool` establish the
command-line conventions to retain:

- lead help with the exact accepted invocation grammar
- generate root and detailed help from the active command descriptors
- describe operation, input, effect, output schemas, and exit statuses
- keep human and JSON errors stable and source-faithful
- separate findings and bounded incompleteness from process failure
- state effect and safety boundaries directly

## Decision

`v0.2.0` adds one command:

```text
ltfa analyze --model-root <directory> --input <file>
  --scope <scope-id> --source <object-id> --target <object-id>
  [--failure <failure-id>] [--format human|json]
  [--include-restricted]
  [--max-candidates <count>]
  [--max-visited-objects <count>]
  [--max-examined-relations <count>]
  [--max-events <count>]
  [--max-state-transitions <count>]
```

The command:

1. loads and compiles one explicitly rooted local model
2. resolves an explicit scope, source, and target by stable external ID
3. checks reachability inside that scope using an undirected view
4. when reachable, runs qualified articulation, bridge, and SPOF analysis
5. optionally propagates one declared failure mode through the complete
   normalized model
6. emits one deterministic human or `ltfa.assurance/v1` JSON result

The explicit scope is required. The command does not infer a site, layer,
service, failure, or observation time.

The active CLI contract version becomes `2`. Existing `model` and `help`
invocations and schemas remain compatible.

## Options

| Option | Contract |
| --- | --- |
| `--model-root` | Required local directory; includes remain below it. |
| `--input` | Required entry file relative to `--model-root`. |
| `--scope` | Required declared scope external ID. |
| `--source` | Required entity or endpoint external ID inside the selected scope. |
| `--target` | Required distinct entity or endpoint external ID inside the selected scope. |
| `--failure` | Optional declared failure-mode external ID. No mode is inferred. |
| `--format` | `human` by default; `json` selects `ltfa.assurance/v1`. |
| `--include-restricted` | Required when the selected analysis can expose restricted model IDs. |
| `--max-candidates` | Positive candidate limit; default `1024`. |
| `--max-visited-objects` | Positive cumulative object-work limit; default `2000000`. |
| `--max-examined-relations` | Positive cumulative relation-work limit; default `10000000`. |
| `--max-events` | Positive propagation event limit; default `1000000`. |
| `--max-state-transitions` | Positive propagation transition limit; default `300000`. |

All count values use strict base-10 unsigned syntax, reject zero, reject signs
and trailing text, and fail before analysis on overflow.

## Result Contract

Human output leads with:

```text
result: complete|incomplete
schema: ltfa.assurance/v1
operation: analyze
focus: <source> -> <target>
scope: <scope>
```

The result then reports:

- scope completeness and evidence quality
- path reachability, representative objects, and relations
- structural status, articulation points, and bridges when applicable
- ordered SPOF findings, classifications, affected targets, common domains,
  retained paths, and remaining unknowns
- optional propagation status, ordered events, affected classifications, and
  work usage
- path, SPOF, and propagation usage and configured bounds

JSON uses the same facts and deterministic array order. Identical model bytes,
arguments, availability baseline, and budgets must produce byte-identical
output.

An unreachable target is a successful complete finding with
`reachable=false`; SPOF classification is `not-applicable` because there is no
baseline selected function path.

Budget exhaustion is a successful structured result with `result=incomplete`
and exit status `0`. A finding is not a process error.

## Restricted Data

Without `--include-restricted`, analysis fails closed before emitting findings
when:

- any object in the selected scope is marked restricted, or
- a requested failure analysis could emit any restricted model object

The explicit flag permits stable IDs only. The assurance output does not emit
attributes, source text, source references, probe payloads, or secret values.

## Errors And Exit Statuses

The command uses existing source-faithful diagnostics and
`ltfa.cli-error/v1`.

| Status | Meaning |
| --- | --- |
| `0` | Complete or bounded-incomplete analysis result. |
| `2` | CLI usage error. |
| `3` | Input, include, or parse failure. |
| `4` | Model or analysis-selection validation failure. |
| `5` | Output failure. |

Unknown command and option suggestions, `--help` conflicts, duplicate options,
required values, and human/JSON routing remain descriptor-backed.

## Safety Boundary

`analyze` is a read-only, one-shot, offline operation. It does not:

- open a socket or resolve a network name
- execute a command or load a plugin
- read observations or infer a live state
- retrieve secrets
- write the model or any external state
- create a tag or publish a release

## Release Boundary

This decision authorizes local `v0.2.0` release preparation through an accepted
candidate. Tagging and publication still require a separate explicit
instruction.
